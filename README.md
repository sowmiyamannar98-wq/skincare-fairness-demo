# Does Bias Propagate? — Fairness in Acne Severity Assessment and Skincare Recommendation

Codebase for the MSc dissertation. Full rationale in
[`MSc_Project_Proposal_Skin_Fairness.md`](MSc_Project_Proposal_Skin_Fairness.md).

The project is a **two-arm, three-corpus** fairness study built as a two-stage
pipeline. The datasets do **not** merge on a shared key — they play distinct
roles:

| Role | Corpus | Kaggle slug | Where it runs |
|---|---|---|---|
| **Arm A** — reference fairness audit (ground-truth tone) | Fitzpatrick17k | `nazmussadat013/fitzpatrick-17k-dataset` | Kaggle GPU (NB2) |
| **Arm B** — applied audit; model the demo runs | ACNE04 | `lexuanhieu131297/acne-severity-classification` | Kaggle GPU (NB3) |
| Recommender catalogue + RQ5 corpus audit | Sephora | `nadyinky/sephora-products-and-skincare-reviews` | Local (scripts) |

> **Hard scope boundary (proposal §5.3):** Fitzpatrick17k / Arm A is a pure
> offline fairness experiment. It is *never* connected to the recommender, the
> ingredient mapping, or the demonstrator.

## Part 2 — Kaggle (image models). GPU, runs overnight.

### One-time setup on Kaggle
1. Go to kaggle.com → **Create → New Notebook**.
2. **File → Import Notebook** → upload `kaggle/nb1_dataprep_ita_gate.ipynb`.
3. Right panel **Add Input** → search and add the three dataset slugs above
   (add all three to NB1; NB2 needs Fitzpatrick; NB3 needs ACNE04).
4. Right panel **Accelerator → GPU T4 x2** (or P100). **Turn on Internet**
   (first run installs `timm`).
5. Repeat import for `nb2_...` and `nb3_...`.

### Run order
1. **NB1** first (CPU, minutes). It prints the input folder trees, derives ITA
   tone bands, validates ITA against ground-truth Fitzpatrick labels, and prints
   the **GO / NO-GO gate** decision. It writes `acne04_ita_labels.csv`,
   `fitz17k_ita_labels.csv`, `gate_decision.json` to the notebook output.
   - *Check the printed folder trees.* If a mirror's layout differs, only the
     small `find_*` / `acne_label` helpers need tweaking — everything else is
     layout-agnostic.
2. **NB2** (Arm A, GPU) — *Save & Run All* → this is the main overnight job.
   Produces `armA_test_predictions.csv` (per-image true/pred/probs + tone band)
   — the artifact the fairness audit consumes.
3. **NB3** (Arm B, GPU) — *Save & Run All*. Optionally add NB1's output as an
   input so it reuses `acne04_ita_labels.csv`; otherwise it recomputes ITA
   inline. Produces `armB_oof_predictions.csv` (out-of-fold, whole corpus).

> Kaggle caps a *Save & Run All* (batch) session at ~12 h and ~9 h GPU. These
> datasets are small enough that a ResNet-50 baseline finishes comfortably
> inside that window. To smoke-test first, set `CFG["max_images"]` (NB2) or a
> low `epochs` and run interactively before committing the full job.

### Interpreting the go/no-go gate (proposal §10.1)
- **GO** → ACNE04's Deep band is dense enough; the applied audit (RQ1/RQ2 on
  Arm B) proceeds as the primary path.
- **NO-GO** → *expected and planned for.* ACNE04's compressed tone range becomes
  a reported finding; Arm A (Fitzpatrick, ground-truth labels) is the primary
  powered audit and RQ5 carries extra analytical weight. **Not a failure.**

## Part 3 — The conversational demonstrator (local, no GPU)

```bash
streamlit run app/app.py
```

Upload a face photo, answer four questions, get explained recommendations.
Architecture per §7.7: this build uses the **rules-based dialogue manager with
no language model in the loop**, so recommendation logic is entirely
deterministic and every suggestion is traceable through the mapping table.

- `app/inference.py` — severity model + abstention (τ = 0.85, derived in
  `reports/08_abstention_threshold.md`, not chosen arbitrarily)
- `app/dialogue.py` — slot filling for skin type / sensitivity / PIH / budget
- `app/safety.py` — specified refusal-and-redirect for medical requests
- `scripts/09_adversarial_test.py` — adversarial prompt set → appendix
  transcripts (**refusal 1.00, false-refusal 0.00**)
